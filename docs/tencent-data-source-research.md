# 腾讯匿名行情端点数据合同研究

## 结论

截至 **2026-08-05 22:01:09（Asia/Shanghai）**，腾讯自有域名上的两个候选端点仍能在无 Token、无 Cookie、无 Referer 的低频请求中返回行情形状：

- 日 K：[`web.ifzq.gtimg.cn/appstock/app/fqkline/get`](https://web.ifzq.gtimg.cn/appstock/app/fqkline/get?param=sh600519,day,,,5,)
- Quote：[`qt.gtimg.cn/q=...`](https://qt.gtimg.cn/q=sh600519,sz000001,sh000001,sh510300)

但当前证据只证明了**一次有界协议观测**，没有形成可供 `chan-quant` 运行时依赖的正式数据合同。核心阻断项是：

1. 本次没有在腾讯官方材料中找到这两个地址的公开开发者字段字典、版本策略、限频、可用性承诺、历史修订策略或端点专属使用许可；

3. 日 K 对 `count` 和 `fqt` 的现场行为不一致：股票请求 `count=2000` 时 `day` 返回 2000 根，但 `qfqday/hfqday` 只返回 641/640 根；指数会静默忽略 `qfq/hfq` 并仍返回 `day`；无效代码仍返回 HTTP `200`、业务 `code=0`；
4. Quote 没有公开字段语义。混合批次中的无效代码会直接缺行；单独请求无效代码则返回 `v_pv_none_match="1";`。本次只在闭市后观察，未验证开盘、连续竞价、午休、收盘切换、停牌和上市首日语义；
5. 两个端点的 HTTP `Content-Type` 都是 `text/html`，而载荷分别表现为 JSON 和 GBK JavaScript 赋值文本，不能依靠 MIME 自动判断协议。

## 与 `chan-quant` 现有合同的对照

### 不替换现有新浪观察标签

[`sina-data-source.md`](sina-data-source.md)把新浪定义为未文档化匿名端点，并用 `unadjusted-observed` 表达有限样本结论。腾讯字段名虽然直接出现 `qfqday/hfqday`，但本次没有完成公司行动经济核验，因此不能比新浪获得更强的正式合同标签。

腾讯当前只能作为注册表中的候选记录，不能新增可选运行模式，也不能把：

```text
qfqday -> qfq confirmed
hfqday -> hfq confirmed
```

写成事实。

### 保持显式模式与失败关闭

[`data-contract.md`](data-contract.md)要求数据源显式选择、远端网络可关闭、snapshot 失败不降级、无效输入与上游故障结构化返回。腾讯的现场行为更需要这些约束：HTTP 和业务 `code` 对无效代码都可能保持成功；复权字段也可能被静默替换。

因此禁止：

```text
腾讯 qfqday 缺失 -> hfqday -> day
新浪失败 -> 腾讯
腾讯失败 -> 新浪或 Yahoo
Quote 缺行 -> 使用上一周期旧值
```

如果将来新增来源，必须由明确配置选择，并把来源、复权、观测时间和错误完整返回。

### 不扩大市场温度匿名源风险

[`a-share-market-breadth-research.md`](a-share-market-breadth-research.md)已经说明匿名网页行情不能定义 universe，也没有正式字段合同、SLA 或再分发授权。腾讯 Quote 的四标的批量成功不能外推为全市场扫描能力；本次没有请求全市场，也不建议将其用于市场温度分母或持续批量抓取。
